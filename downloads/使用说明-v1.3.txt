VVebo 1.3 启动崩溃修订测试版

本版针对用户上传的 v1.2 崩溃记录修复补丁代码错误。尚未完成真机启动验证，不能保证所有故障已解决。黑边处理继续关闭。

已定位的问题
最新记录的构建号为 4.12，补丁 Framework 已成功加载；此次不再是之前的加载阶段签名拒绝。
致命线程为 objc_msgSend → objc_setAssociatedObject → 补丁 Hook。
旧版保存方法地址的自定义类具有错误内存布局，编译指令将方法地址写到了对象头（isa）位置。
另一种自定义响应缓存对象也受同一不完整基础类声明影响，因此一并移除。
这是补丁代码缺陷，无需为此更换证书。

v1.3 变更
- 方法地址由系统 NSValue 保存。
- 响应缓存直接使用系统 NSMutableData。
- 完全移除两种自定义 Objective-C 存储类及直接 ivar 写入。
- 补充基础对象头声明，并检查最终补丁不包含自定义 Objective-C 类元数据。
- 保留 v1.2 的标准 LLVM Framework 构建与主页适配逻辑；窗口填充仍关闭。
- 构建号 4.13，桌面名称 VVebo 1.3。

针对性验证
在 ARM64 Unicorn 模拟器中执行真实编译后的 Hook，系统 API 以测试替身提供：
- v1.2 的机器码复现对象头被原方法地址覆盖的行为。
- v1.3 的机器码保留对象头，并通过模拟 NSValue API 保存完全相同的方法地址。
此测试直接覆盖日志所指的内存破坏路径，但不是 Foundation、系统签名、完整 iOS App 或真机行为的模拟。
另通过编译、ZIP、变更范围、原程序指令、Framework 元信息、库加载路径、段布局、构造入口、系统符号及代码页/资源签名检查。

全能签测试步骤
1. 重新下载并导入 v1.3 文件，重新签名安装；不要复用旧的已签名包。无需先删除原 App。
2. 桌面应显示 VVebo 1.3。先检查是否能启动。
3. 若能启动，关闭 QX 中 VVebo 专用重写，再检查博主主页、刷新及翻页。
4. 如果仍闪退，请上传该次新生成的 VVebo .ips 文件，必要时再检查签名后的 v1.3 IPA。
