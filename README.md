## 最新崩溃记录的明确结论

v1.2 的 Framework 已成功加载。致命调用链为 `objc_msgSend → objc_setAssociatedObject → Hook`，与此前签名加载拒绝不同。

旧补丁的自定义方法指针存储对象使用了错误的 ivar 布局，真实编译指令把原方法地址写入对象头。v1.3 移除两种自定义存储对象，分别使用系统 `NSValue` 和 `NSMutableData`，不再直接写自定义 ivar，并检查最终库中没有自定义类元数据。

## 针对性验证与限制

使用 Unicorn ARM64 模拟执行真实编译后的 Hook，系统 API 由测试替身提供。旧版复现了覆盖对象头的行为；新版保留对象头并正确保存方法地址。这个测试直接覆盖日志指向的损坏路径，但不模拟 Foundation、签名、完整应用或真实设备。

另外通过了交叉编译、ZIP、精确变更范围、原应用指令保留、Framework 元信息、段布局、加载路径、初始化入口、系统符号来源和代码页/资源签名结构检查。

**未验证：** v1.3 的设备签名接受、完整启动、在线接口/翻页、其他页面与黑边效果。Linux 云环境不能运行 UIKit 应用。

主页转换算法参考用户已确认有效的 [bin64 QX 脚本](https://raw.githubusercontent.com/bin64/Scripts/main/QuantumultX/vvebo.js)。不引入额外代理，不记录鉴权信息。原始崩溃日志、用户签名后的 IPA、证书和设备信息不在此仓库公开。
