用户上传的日志显示：系统在启动阶段因新增 `VVeboPatch.dylib` 的 **代码签名无效** 而拒绝加载，补丁逻辑尚未运行。此报告内动态库标识对应初版测试包，与 v1.1 不同，不能据它确认 v1.1 的具体终止原因。此前系统符号提供库修正不是这份日志所显示的原因。

当前需要核实实际签名/安装工具以及当前版本的签名结果，而非继续修改主页接口或黑边逻辑。原始崩溃日志含设备信息，不在仓库公开。

## 修改与验证范围

主页补丁参考用户提供并确认有效的 [bin64 QX 脚本](https://raw.githubusercontent.com/bin64/Scripts/main/QuantumultX/vvebo.js)：切换主页列表接口，转换翻页参数及返回卡片格式。在本地应用内处理，不引入额外代理服务器、不记录鉴权信息。

通过了 arm64 交叉编译、系统符号导入来源比对、ZIP、加载命令、依赖绑定、补丁启动入口、代码页/资源签名结构检查；保留原应用指令、身份和权限声明。QX 参考算法仅用合成数据验证。

Linux 云环境无法运行 UIKit 应用。没有完成真机启动、正式签名、在线接口、翻页或黑边验证。结构检查通过不证明修复成功。
