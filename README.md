## 本次诊断与修订

崩溃记录显示新增补丁库在启动加载时被系统以代码签名无效拒绝。检查用户随后导出的 v1.1 已签名 IPA，主程序、补丁和原有框架签名证书/团队一致，代码页、特殊槽及 CMS 密码学签名检查通过。因此没有证据表明是简单漏签；这些离线结果不等于设备信任检查通过。

v1.2 改用标准 LLVM LLD 19.1.7，代码及数据段采用 iOS arm64 的 16 KB 布局，并将补丁封装为嵌入式 `VVeboPatch.framework`，供签名工具按框架处理。此前构建工具的段布局与正常框架不同；这是一项有依据的兼容性修订，尚未证明该差异就是闪退根因。

主页算法参考用户已验证有效的 [bin64 QX 脚本](https://raw.githubusercontent.com/bin64/Scripts/main/QuantumultX/vvebo.js)。本地处理请求与响应，不引入外部代理，不记录鉴权信息。
