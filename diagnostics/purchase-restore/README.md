# “没有找到购买记录”提示的核对

用户说明：以前购买过 Pro，目前仍使用购买时的 Apple ID；恢复购买按钮可点击，但显示没有购买记录。用户随后确认是 App 内订阅，之后明确将需求改为解除本地会员功能限制。原订阅有效期核对不再是当前本地功能版本的前置要求。

## 已核对的客户端逻辑

- App 内原有 SwiftyStoreKit.restorePurchases 调用与收据处理仍保留，没有在兼容包中替换成购买失败或成功。
- 自动及手动恢复的回调分别经 0x126424、0x3dda98 进入原函数 0x11ab50。
- 该函数读取恢复列表的元素数，列表为空即进入 0x11acd8，随后显示 0x5cebb0 的“没有找到购买记录”。这条提示未展示完整失败原因，不能据此认定用户未购买。
- 该空结果分支发生在后续获取收据的路径之前；重新启用 CloudKit 不能被当成解决当前空恢复结果的办法。
- 原程序包含多种月付、年付及永久 Pro 产品标识。独立付费 App 的购买也不能直接当作此 Bundle ID 下的内购；需要先匹配原订单类型。

ARM64 检查仅用模型数组执行原函数的入口分支：恢复列表为 0 时，无论模型失败列表为 0 或 1，都走同一无记录分支；恢复列表为 1 时走后续处理。没有访问 App Store、取得真实交易或授予会员状态。

```bash
PYTHONPATH=/path/to/unicorn python3 diagnostics/purchase-restore/check_empty_result.py /path/to/current.ipa
```

## 签名与收据线索

对用户此前提供的实际重签文件作了重新核对：Info.plist 的 Bundle ID 保持原版，但签名及配套描述文件的 application-identifier 后缀与它不一致；签名与描述文件的 application-identifier 相互一致。这是应用身份配置问题，可能影响 StoreKit 对原购买的识别，不能仅凭这一项断言所有空恢复结果的唯一原因。

公开的兼容 IPA 不自带 App Store 收据，不包含用户的证书或购买凭证。离线检查不能查看该用户当前设备上 StoreKit 实际返回的错误、交易或有效授权。仍需核对购买类型及可验证的原购买结果，不能通过伪造本地购买状态替代恢复。

当前已制作独立的本地 Pro 功能测试版，不能把它理解为恢复了 App Store 交易、订阅或云端权限；原购买恢复仍没有被证实成功。本文不包含 Apple ID、证书标识、设备标识、交易号、描述文件或购买收据。
